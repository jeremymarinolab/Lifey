# Lifey

Lifey is a local-first personal workspace that runs as a static browser app backed by a small Python helper on the Mac. The helper serves the UI, reads and updates local Obsidian notes, stores sensitive integration credentials in the macOS Keychain, and exposes narrow local APIs for optional integrations.

For coding-agent handoff rules and project-specific implementation constraints, see [`agents.md`](./agents.md).

## Quick Start

```sh
npm start
```

Open `http://localhost:4173`.

For access from an iPhone or another device on the same Wi-Fi:

```sh
npm run start:lan
```

Open `http://YOUR-MAC-WIFI-IP:4173`.

## Architecture

- **Frontend shell:** `index.html`, `app.js`, and `js/` implement the browser UI. State is normalized in `js/state.js`, API response guards live in `js/api.js`, and feature controllers live under `js/features/`.
- **Styling:** shared foundations live in `styles.css`, `dashboard-layout.css`, `settings-panels.css`, and `mobile.css`. Feature-owned card styles live in the `*-card.css` files.
- **Backend helper:** `local_server.py` serves the app and dispatches API routes registered in `routes.py`.
- **Domain services:** backend behavior is split into focused modules such as `task_service.py`, `project_service.py`, `habit_service.py`, `activity_service.py`, `places_service.py`, `profile_service.py`, `archive_service.py`, and `obsidian_repo.py`.
- **Integration clients:** `google_client.py` and `notion_client.py` hold provider-specific request code. Spotify is handled on the frontend through `js/integrations/spotify.js`.
- **Persistence:** browser display state is stored in `localStorage`; Mac-side profile/config lives in `~/Library/Application Support/Lifey/profile.json`; private tokens are stored in the macOS Keychain under service `Lifey`.
- **PWA cache:** `service-worker.js` caches the app shell. Its cache list is generated by `scripts/sync-asset-version.mjs` from `index.html`, JS imports, and `manifest.webmanifest`.

## Commands

```sh
npm start
```

Runs Lifey on localhost. The `prestart` hook updates asset versions first.

```sh
npm run start:lan
```

Runs Lifey with `LIFEY_LAN=1` so the Mac helper can bind for LAN access.

```sh
npm run assets:version
```

Recomputes the app-shell hash, updates `?v=` query strings in `index.html`, and regenerates the service worker shell cache list.

```sh
npm run check
```

Runs asset-version validation, format checks, lint checks, Python and Node unit tests, and browser smoke tests.

```sh
npm run lint
```

Runs lightweight JS syntax, Python compile, and CSS brace checks across source files.

```sh
npm run format:check
```

Checks source files for consistent line endings, trailing whitespace, and final newlines.

```sh
npm run format
```

Applies the lightweight whitespace/newline formatter to JS, CSS, and Python files.

```sh
npm test
```

Runs the Python and JavaScript test suites.

## Mac Autostart

The login-agent installer lives in `scripts/install-lifey-autostart.sh`.

```sh
./scripts/install-lifey-autostart.sh
```

It installs a LaunchAgent named `com.lifey.app`, generates paths for the current checkout, removes the old `com.lifey.dashboard` LaunchAgent if present, and starts Lifey with `scripts/start-lifey.sh`.

Logs are written to:

- `~/Library/Logs/Lifey/lifey.log`
- `~/Library/Logs/Lifey/lifey-error.log`
- `~/Library/Logs/Lifey/traccar-startup.log`

## Storage And Secrets

Lifey deliberately separates normal preferences from secrets.

- Non-secret Mac config: `~/Library/Application Support/Lifey/profile.json`
- Legacy config read path: `.local-dashboard.json`
- Secret store: macOS Keychain service `Lifey`
- Secret keys include Notion tokens, Traccar tokens, Google refresh tokens, Google client secrets, Google Places keys, and the Lifey Location collector token.

`config_store.py` fails closed when a secret cannot be written to Keychain. Profile export/import strips secret fields so exported settings can be moved without leaking credentials.

## Local API Boundary

The backend route table is defined in `routes.py`. Routes are grouped by domain and validate JSON request bodies before dispatch. Browser-origin protection is enforced for local API calls, with narrow exceptions for the browser extension activity endpoints and mobile location ingest.

Key route groups include:

- tasks and projects
- habits
- calendar and Google OAuth
- Notion sync
- activity and YouTube capture
- location, places, and mobile ingest
- profile export/import
- archive generation

## Obsidian Contract

Lifey treats Obsidian as a local repository, not a remote API.

- Daily note discovery and filesystem helpers live in `obsidian_repo.py`.
- Task records keep source path and line metadata where possible.
- Archive writes replace only the marked Lifey archive block.
- Before writing an archive update, the helper creates a timestamped sibling backup.
- Habit-section checkboxes are protected from task actions and handled through the Habits card.

## Integrations

All integrations are optional. The UI should make degraded or disconnected states visible instead of pretending an integration is healthy.

- **Notion:** configured through a token and database/data-source ID; request logic lives in `notion_client.py`.
- **Google Calendar/Gmail:** OAuth and API calls live in `google_client.py`; secrets and refresh tokens are Keychain-backed.
- **Spotify:** frontend OAuth state and playback/profile handling live under `js/integrations/spotify.js`.
- **Traccar:** optional location source. `scripts/start-lifey.sh` can resume an existing Docker Traccar container, but Lifey does not require it.
- **OpenStreetMap/Google Places:** optional place enrichment from `places_service.py`.

## Browser Extension

The Zen/Firefox extension in `browser-extension/` captures visible, focused YouTube watch-page activity and posts it to the local helper.

Install for development:

1. Start Lifey with `npm start`.
2. Open `about:debugging#/runtime/this-firefox`.
3. Choose **Load Temporary Add-on**.
4. Select `browser-extension/manifest.json`.

Package for signing:

```sh
./browser-extension/package.sh
```

The extension ID is `lifey-youtube@local`.

## iOS Location Companion

`LifeyLocation/` contains the Swift iOS companion app. It queues location samples on-device and uploads batches to the Mac helper when reachable.

Operational flow:

1. Start Lifey on the Mac in LAN mode.
2. In Lifey, create or rotate the mobile collector token.
3. Build and install the iOS app from `LifeyLocation.xcodeproj`.
4. Enter the Mac base URL and collector token in the iOS app.
5. Grant location permission and enable tracking.

The ingest endpoint validates batch shape, rate-limits by client/token fingerprint, rejects duplicates/replays, and stores samples under `~/Library/Application Support/Lifey/location-samples.json`.

## Asset Versioning And Cache

Do not edit the service worker shell list by hand.

`scripts/sync-asset-version.mjs` derives app-shell assets from:

- local `href` and `src` references in `index.html`
- static JS imports reachable from versioned scripts
- icon assets declared in `manifest.webmanifest`

The script hashes those files, updates the version query strings, and rewrites the generated shell block in `service-worker.js`. `npm run check` fails if the asset version is stale or if a referenced local shell asset is missing.

`js/app-updates.js` compares the version embedded in the loaded page with the version reported by the controlling service worker. When a new worker activates, Lifey announces the update and reloads once; a per-version session guard prevents reload loops. Settings → Profile shows both versions and includes controls to check for updates or clear only Lifey's app-shell caches.

Browser tests run their local helper on port `4174` by default so they do not reuse or interrupt the normal Lifey server on port `4173`. Set `LIFEY_TEST_PORT` to override the test port.

## Tests

Python tests live in `tests/test_local_server.py`.

JavaScript tests live in `tests/js/*.test.mjs`.

The current test suite covers route registration/security behavior, request validation, Keychain fail-closed behavior, profile secret stripping, mobile location ingest hardening, parser logic, state normalization, response normalization, and pure feature-controller state transitions.

Run everything with:

```sh
npm run check
```

## Development

Use the Commands and Tests sections above for local validation. Agent-specific workflow rules, product boundaries, and implementation cautions live in [`agents.md`](./agents.md) to keep this README focused on human onboarding and project setup.

Keep the canonical checkout on `main`. Create a separate branch and sibling worktree for each meaningful feature, bug fix, or refactor so unfinished work does not accumulate in the running copy of Lifey:

```sh
git fetch origin
git worktree add ../worktrees/feature-name -b codex/feature-name origin/main
cd ../worktrees/feature-name
```

Run the appropriate checks, commit and push the focused change, merge it through a pull request, and then remove its worktree:

```sh
git worktree remove ../worktrees/feature-name
git branch -d codex/feature-name
```

Do not use a worktree for a second task until the first task's changes have been committed or deliberately preserved on its own branch.
